# 动态仓位管理设计与落地

本文件定义本项目的动态仓位管理方案与可落地执行细节，覆盖波动率目标、资金/回撤自适应、信号强度分级、相关性/集中度、事件/时段过滤与执行约束，并给出 MNQ（日内）合约的可计算公式与运行规则。

---

## 1. 目标与原则
- 目标：在不牺牲风险控制的前提下提升资金效率，使每笔交易风险可比、可控、可度量。
- 原则：风险先行、动态自适应、以波动定仓、统一到“每笔风险 R”的标准化框架下。

## 2. 核心要点（方法论）
1) 波动率目标（Vol Target）
- 用近期波动（如 14–20 日 ATR，或日内真实波动 RV）把每笔风险标准化；波动大→降杠杆，波动小→升杠杆。
- 计算建议：
  - 日线：ATR(N=14~20)；
  - 日内：真实波动 RV，基于近 N 根 M5/K 线的 True Range 或标准化收益率。

2) 资金/回撤自适应（DD Adaptive）
- 当权益创新低或达到回撤阈值时，分档减仓；例如回撤每增加 2%，整体仓位乘以 0.7。
- 回撤恢复后可按分档规则缓慢恢复（可配置“冷启动”/“恢复坡度”）。

3) 信号强度分级（Signal Tiering）
- A 级信号满配，B 级半配，C 级不做；避免“弱信号大仓位”。
- 信号强度来源：多因子合成分、置信度、长期胜率/赔率统计等。

4) 相关性/集中度（Correlation/Concentration）
- 高度同向的品种/策略视为“一笔风险”，合并后再定总仓，避免名义分散、实则集中。
- 采用滚动相关矩阵、行业/主题聚类或 PCA 衡量聚合风险。

5) 事件/时段过滤（Event/Session Filter）
- 重大数据公布、流动性真空（如开盘首分钟/收盘最后分钟、夜盘极冷清时段）自动降半或清仓。
- 事件来源：经济日历、定时窗口、波动/点差阈值触发。

6) 执行约束（Execution Constraints）
- 每个品种设置“流动性上限”（成交量/盘口深度阈值）与“滑点预算”（期望最大滑点），任一超标即降仓或拒单。
- 记录实时成交与滑点，形成动态限额与“滑点信用分”。

---

## 3. 变量定义与统一记账
- Equity：账户权益（实时/日内更新）。
- r：每笔风险占比（例如 0.3%）；R = Equity × r。
- S：技术止损距离（点）。
- point_value：每点合约价值（MNQ 为 $2/点）。
- RV：真实波动度量（滚动窗口的 True Range 或收益率标准差）。
- Scale_vol：波动率调节因子（示例：RV_ref / RV_current）。
- Scale_dd：回撤调节因子（按回撤分档相乘累计）。
- Scale_sig：信号分级因子（A=1，B=0.5，C=0）。
- Scale_exec：执行约束因子（基于流动性/滑点，0~1）。

总的目标仓位因子：Scale_total = Scale_vol × Scale_dd × Scale_sig × Scale_exec（并对区间进行裁剪，如 [0, 1]）。

---

## 4. 通用头寸公式（单品种）
- 基础风险预算：R = Equity × r。
- 波动率调节：R* = R × Scale_vol（例：Scale_vol = RV_ref / RV_current）。
- 回撤/信号/执行叠加：R** = R* × Scale_dd × Scale_sig × Scale_exec。
- 合约数（整数向下取整）：
  - contracts = ⌊ R** / (point_value × S) ⌋。
- 约束：contracts ≥ 0；若 contracts = 0，且信号为 C 或执行约束触发，则不做。

组合/多品种：
- 对高度同向组（相关性阈值 > ρ0）先合并预算 R_group，再按组内边际波动或等风险分配到单品种。

---

## 5. MNQ（日内）落地公式与规则
- MNQ 点值：point_value = $2/点。
- 设定每笔风险：R = Equity × r（如 r = 0.3%）。
- 技术止损距离：S（点），由策略给定（如基于近 N 根 M5 的结构/波动）。
- 合约数：contracts = ⌊ R / (point_value × S) ⌋（随后再乘以 Scale_total 并取整）。
- 波动率调节：用近 N 根（如 20 根 M5）的真实波动 RV，将目标风险按 RV 的比值缩放（例：R* = R × RV_ref / RV_current）。
- 日内断路器（Circuit Breaker）：
  - 若当日亏损 ≥ 3R 或连续亏损 3 笔，停止交易至次日或冷却期结束。
  - 断路器触发后，清空未成交与挂单，记录原因与恢复条件。

---

## 6. 集成与运行时控制
- 事件/时段过滤：在进入/加仓前检查事件窗口与流动性阈值，必要时降半或不做。
- 执行约束：计算“预估滑点”与“流动性上限占比”，若超标则下调 Scale_exec 或拒单。
- 回撤自适应：
  - 回撤每增加 2%：Scale_dd *= 0.7；
  - 可设置最大阶数与恢复规则（如回撤修复后逐级恢复）。
- 信号强度：策略产出 A/B/C 等级，映射 Scale_sig ∈ {1, 0.5, 0}。
- 相关性/集中度：使用滚动相关矩阵，按行业/主题聚类后分配组预算。

---

## 7. 参数建议（可通过 .env/DB 配置）
- RISK_PER_TRADE_R = 0.003（0.3%）
- VOL_WINDOW = 20（M5 根数或日线天数）
- RV_REF_METHOD = median_60d 或 long_run_mean
- DD_STEP = 0.02，DD_SCALE = 0.7，DD_MAX_STEPS = 5
- SIGNAL_TIERS = {A:1, B:0.5, C:0}
- EXECUTION_LIMITS = {min_volume, max_spread, max_slippage}
- EVENT_FILTERS = {macro_release, session_cooldown}
- CONTRACT_ROUNDING = floor

---

## 8. 对接点（无需立即改代码的设计接口）
- 风控层：提供 position_sizing(realtime_state, signal, S, RV_current) → contracts_suggested。
- 订单流：在 place_order 前接入 position_sizing 输出；若 contracts_suggested = 0 则拒单或改为观望。
- 监控层：记录因子（Scale_vol/dd/sig/exec）与断路器状态，便于回测与复盘。
- 可视化：新增“仓位建议/实际执行/偏离”面板与日内断路器状态展示。

---

## 9. 测试与验证
- 单元测试：
  - 波动率变化下，contracts 单调合理；
  - 回撤分档后 Scale_dd 正确叠加；
  - 事件/执行约束触发后合约数下降或为 0。
- 历史回测：
  - 与恒定手数对比，最大回撤下降、收益回撤比提升；
  - 断路器有效降低尾部风险。
- 实盘跟踪：
  - 记录建议 vs 实际，调参与裁剪区间，形成稳定的 Scale_total 分布。

## 10. .env 与 UI 配置清单（规划）
- 目标：将动态仓位管理与断路器关键参数统一由.env/.env.local管理，并在Web界面“设置 > 风控 > 动态仓位”以及“设置 > 事件/会话”中提供编辑能力，修改后写入配置源并触发后端规则刷新。

- 建议变量与默认值（与高级风控方案保持一致）：
  - RISK_PER_TRADE_R=0.003（每笔风险r=0.3%）
  - VOL_WINDOW=20（RV滚动窗口，M5根数或日线天数）
  - RV_REF_METHOD=median_60d（RV参考基准）
  - DD_STEP=0.02（回撤分档步长）
  - DD_SCALE=0.7（每档回撤缩放）
  - DD_MAX_STEPS=5（最大回撤分档数）
  - SIGNAL_TIERS=A:1,B:0.5,C:0（信号分级因子）
  - EXECUTION_LIMITS.min_volume（最小成交量阈值）
  - EXECUTION_LIMITS.max_spread（点差上限）
  - EXECUTION_LIMITS.max_slippage（滑点预算上限）
  - EVENT_FILTERS.macro_release（宏观事件开关或白名单）
  - EVENT_FILTERS.session_cooldown（会话冷却窗口配置）
  - MNQ_POINT_VALUE=2（MNQ点值）
  - CONTRACT_ROUNDING=floor（合约取整方式：floor/round/bankers）
  - CIRCUIT_BREAKER_DAILY_R=3（当日累计亏损R阈值）
  - CIRCUIT_BREAKER_STREAK=3（连亏笔数阈值）

- UI交互建议：
  - 采用分组表单：基础风险、波动/回撤、信号分级、执行约束、事件/会话、断路器；
  - 提供“预设方案”下拉（保守/标准/激进），一键写入一组推荐值；
  - 提供“重置为默认值”按钮；
  - 保存后通过WebSocket广播配置变更，后端热加载；
  - 面板展示当前Scale_total分解（vol/dd/sig/exec）与断路器状态，并给出建议合约数与解释文本。

- 数据持久化策略：
  - 首选.env.local；若需审计与多租户，则同时写入SQLite配置表（由database.py维护），保留修改历史。
