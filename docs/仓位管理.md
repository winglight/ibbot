# 动态仓位管理设计与落地

本文件定义本项目的动态仓位管理方案与可落地执行细节，覆盖波动率目标、资金/回撤自适应、信号强度分级、相关性/集中度、事件/时段过滤与执行约束，并给出横跨**期货（MNQ/NQ/ES/MES）与个股（Shares）**的**规则引擎 + 前端面板**一体化实现。
在本版中，我们将“方法论”系统化为 **S 规则（Sizing Policy）**，并与 **G 规则（Guardrails）**统一在一个面板中，通过**标签页**区分（方案 A）。

---

## 1. 目标与原则

* **目标**：在不牺牲风险控制的前提下提升资金效率，使每笔交易风险**可比、可控、可度量**；把“该做做大、不该做减少/不做”的理念落地到**软硬结合**的 S/G 体系。
* **原则**：风险先行、动态自适应、以波动定仓、统一到“每笔风险 R”的框架；**所有放大（杠杆）行为必须有与之匹配的风控**。

---

## 2. 核心要点（方法论 → S 规则）

1. **波动率目标（Vol Target）**
   用近期波动把每笔风险标准化；波动大→降杠杆，波动小→升杠杆。

   * 日线：ATR(N=14\~20)；日内：真实波动 RV，基于近 N 根 M5/K 线的 True Range 或收益率。
2. **资金/回撤自适应**
   账户权益 Eq 与近期最大回撤 MDD 共同决定“风险预算”；MDD 越深、预算越低。
3. **信号强度分级（可与盘口/结构一致性融合）**
   `trend_score ∈ [-1,1]`；`fake_breakout_prob ∈ [0,1]`；一致性越强→仓位因子更高。
4. **相关性/集中度约束**
   跨品种或同方向集中交易时，对总敞口或风险叠加做约束（按组上限）。
5. **执行与风控优先级**
   **G（硬限制） > S（建议） > 策略建议仓位 > 执行细节（滑点/指令/排队）**。

---

## 3. 基础定义与记号

* **Eq**：账户权益（USD）
* **r**：每笔风险占比（默认 0.3%\~0.5%）
* **R = Eq × r**（每笔容忍亏损，USD）
* **S**：止损距离（点/价差）
* **point\_value**：每点价值（例：MNQ = \$2/点）
* **期货单位数**：`N = floor( R / (point_value × S) )`（再叠加缩放与取整）
* **个股股数**（风险驱动）：`shares = floor( R / |Entry - SL| )`

---

## 4. 日内（MNQ）推荐默认

* `r = 0.003`（0.3%），`S` 取 ATR 或结构/盘口止损位到入场价的点数。
* 建议 `N ≥ 1` 时下单，否则不下或延迟。

---

## 5. 动态缩放因子（示例）

* 结构/盘口一致性：`f_sig ∈ {0.25, 0.5, 1.0}`
* 波动与回撤：`f_vol, f_dd ∈ (0, 1]`
* 实际下单：`N_real = max(1, floor( N × f_sig × f_vol × f_dd ))`

---

## 6. 账户级断路器（基础）

* 当日亏损 ≥ **3×R0** 或连续亏损 ≥ 3 笔 → **停止当日交易**。
* 强平事件后遵循 G 规则（见第 9 章）。

---

## 7. 与策略/盘口模块对接

* **策略产出**：方向、入场价、止损 S、（可选）止盈、置信度/评分。
* **盘口产出**：`trend_score`、`fake_breakout_prob`、`wall_state`。
* **统一交付**给“仓位计算（S） + 规则引擎（G） + 执行控制”。

---

## 8. 指标与日志

* 记录每笔：Eq、R、S、N（建议/实际）、缩放因子、规则命中、下单/成交/退出原因。
* 便于复盘与参数自适应。

---

## 9. 统一规则体系（S & G）与页面设计（方案 A：一个面板 + 标签）

> 将方法论落地为 **S 规则（Sizing Policy，建议）**，并用 \*\*G 规则（Guardrails，硬限制）\*\*保障组合安全。
> 左侧“Position & Risk Controls”面板新增 **Tabs：`G规则` / `S规则`**；右侧“Notifications”面板保持不变。
> **下单弹窗**仅展示 **S 规则即时建议**（只读），不做配置修改。

### 9.1 S 规则（Sizing Policy：按方法论算“该下多少仓”）

流程：**S0→S1→S2→S3→S4→S5→S6→S7→S8**，得出 `N_sizing`（建议仓位），再交给 G 规则审查与裁剪。

* **S0｜资格与时段过滤（事件/时段）**
  可交易时段、黑名单事件窗口（财报、FOMC 等）。
  *UI*：交易所/品种时段、禁入窗口模板。
* **S1｜每笔风险预算 R（资金/回撤自适应）**
  `R0 = Eq × r_base`；`f_dd(MDD)`（例：0~~5%→1.0；5~~10%→0.7；>10%→0.5）→ `R = R0 × f_dd × f_vol_acct(可选)`。
* **S2｜止损距离 S（以波动定仓）**
  优先：`S_strategy` > `ATR×N` > `最小tick×k`； `S = max(...)`。
  *UI*：ATR 窗口、N 倍数、最小 S。
* **S3｜基础单位数**
  期货：`N0 = floor( R / (point_value × S) )`；
  个股（风险驱动）：`shares0 = floor( R / |Entry - SL| )`。
* **S4｜信号/一致性缩放**
  `f_sig`（0.25/0.5/1.0 或线性组合），`N1 = floor(N0 × f_sig)`。
* **S5｜目标波动率校准（可选）**
  `f_vol = target_vol / realized_vol_recent`（裁剪到 `[0.5, 1.5]`），`N2 = floor(N1 × f_vol)`。
* **S6｜相关性/集中度（组合层）**
  分组风险/敞口上限，计算 `f_corr` 约束 `N3`。
* **S7｜成交/深度约束（Level 2） & 个股预算驱动**
  以 Xbps 内深度与冲击上限，得 `N_exec_cap`；预算驱动个股：`budget = Eq/divisor_shares`。
  `N4 = min(N3, N_exec_cap)`；或 `shares4 = min(shares3, shares_budget)`。
* **S8｜整手与最小值**
  交易所步进/整手/最小合约取整；输出 `N_sizing` 与“因子拆解”用于复盘。

> S 规则的**参数设置与历史记录**在主页面 S 标签中；**下单弹窗**只展示即时计算结果，不改配置。

### 9.2 G 规则（Guardrails：账户/组合硬限制）

执行顺序严格：**G7→G6→G5→G4→G3→G2→G1**。

* **G7｜跨日停交易（强平后锁定）**
  触发 T2 强平后，**暂停之后两天**（第 3 个交易日恢复）。
* **G6｜当日停/冷却（行为）**
  当日两笔亏损→停止当日；单笔亏损→冷却 120 分钟（可配）。
* **G5｜日内交易次数上限**
  美东 0:00–24:00 **最多 3 次**（开+平计 1 次）。
* **G4｜杠杆感知的亏损阈值（通知/强平）**
  三种基准（可组合）：

  1. `Equity/L：T = Eq × pct_equity / max(1, L)`
  2. `保证金：T = total_initial_margin × pct_margin`
  3. `敞口：T = gross_exposure × pct_exposure`
     触发：`loss_abs ≥ T1` → 通知；`≥ T2` → **强平 + 限制新单**（并触发 G7）。
* **G3｜浮亏禁止加仓**
  任一方向浮亏时，禁止同向加仓。
* **G2｜排队/滑点与挂单限制**
  前单未完全成交→禁再下同向单；滑点超阈→阻断。
* **G1｜资产级硬上限（保证金×缓冲；单笔≤1/4）**
  期货：`max_lots = floor( Eq / (initial_margin × buffer) )`；单笔上限 `= floor(max_lots × 0.25)`；
  个股：在 S 结果基础上受组/资产上限裁剪（名义/仓占比等）。

## 12. 接口与数据流（要点）

* **S 配置**
  `GET/PUT /api/sizing/policy`（全局 + 资产级参数）
  `GET /api/sizing/history?symbol=&since=`（S 建议历史）
* **S 预览（下单弹窗）**
  `POST /api/sizing/preview` → `{ N, explain: { R, S, point_value, f_sig, f_vol, f_corr, depth_cap, ... } }`
* **G 校验**
  `POST /api/orders/validate`（执行顺序 `G7→G6→G5→G4→G3→G2→G1`；可附 `sizing_explain`）
* **下单**
  `POST /api/orders/place`（内部先 `validate`，通过才执行）
* **事件/日志**
  `GET /api/events?type=&rule=&since=`（仓位/风控事件）
* **通知**
  设置：`GET/PUT /api/notifications/settings`
  历史：`GET /api/notifications/history?status=&channel=&since=`
  测试：`POST /api/notifications/test`
* **WebSocket `/ws/stream`**
  推送：`event`（规则事件）、`notification`（发送结果）、`risk_state`（次数/冷却/停牌）、`order_validation_failed`（阻断原因）、`sizing_preview`（可选）

## 13. 示例：MNQ 一次建议与校验（带入实参）

假设 `Eq = 100,000`、`r_base = 0.003`、`MDD ≤ 5% → f_dd = 1.0`、`S = 25 点`、`point_value = 2`：

* **S1**：`R = 100000 × 0.003 = $300`
* **S3**：单合约风险 `= S × PV = 25 × 2 = $50` → `N0 = floor(300/50) = 6`
* **S4**：若 `f_sig = 0.5` → `N1 = 3`（未触发 S5\~S7 时 `N_sizing ≈ 3`）
* **G1**：`max_lots = floor( 100000 / (3479.31 × 1.4) ) = floor(20.5) = 20`；单笔上限 `= floor(20 × 0.25) = 5` → 建议 3 手**不受限**
* **G2/G3/G4/G5/G6/G7**：按当前状态判定（如无触发则通过）。

## 14. 测试清单（覆盖 S 与 G）

1. **S 计算链**：S0\~S8 全路径；不同 ATR、评分与深度场景下的 `N_sizing` 正确性。

# 动态仓位管理设计与落地

本文件定义本项目的动态仓位管理方案与可落地执行细节，覆盖波动率目标、资金/回撤自适应、信号强度分级、相关性/集中度、事件/时段过滤与执行约束，并给出横跨**期货（MNQ/NQ/ES/MES）与个股（Shares）**的**规则引擎 + 前端面板**一体化实现。
在本版中，我们将“方法论”系统化为 **S 规则（Sizing Policy）**，并与 **G 规则（Guardrails）**统一在一个面板中，通过**标签页**区分（方案 A）。

---

## 1. 目标与原则

* **目标**：在不牺牲风险控制的前提下提升资金效率，使每笔交易风险**可比、可控、可度量**；把“该做做大、不该做减少/不做”的理念落地到**软硬结合**的 S/G 体系。
* **原则**：风险先行、动态自适应、以波动定仓、统一到“每笔风险 R”的框架；**所有放大（杠杆）行为必须有与之匹配的风控**。

---

## 2. 核心要点（方法论 → S 规则）

1. **波动率目标（Vol Target）**
   用近期波动把每笔风险标准化；波动大→降杠杆，波动小→升杠杆。

   * 日线：ATR(N=14\~20)；日内：真实波动 RV，基于近 N 根 M5/K 线的 True Range 或收益率。
2. **资金/回撤自适应**
   账户权益 Eq 与近期最大回撤 MDD 共同决定“风险预算”；MDD 越深、预算越低。
3. **信号强度分级（可与盘口/结构一致性融合）**
   `trend_score ∈ [-1,1]`；`fake_breakout_prob ∈ [0,1]`；一致性越强→仓位因子更高。
4. **相关性/集中度约束**
   跨品种或同方向集中交易时，对总敞口或风险叠加做约束（按组上限）。
5. **执行与风控优先级**
   **G（硬限制） > S（建议） > 策略建议仓位 > 执行细节（滑点/指令/排队）**。

---

## 3. 基础定义与记号

* **Eq**：账户权益（USD）
* **r**：每笔风险占比（默认 0.3%\~0.5%）
* **R = Eq × r**（每笔容忍亏损，USD）
* **S**：止损距离（点/价差）
* **point\_value**：每点价值（例：MNQ = \$2/点）
* **期货单位数**：`N = floor( R / (point_value × S) )`（再叠加缩放与取整）
* **个股股数**（风险驱动）：`shares = floor( R / |Entry - SL| )`

---

## 4. 日内（MNQ）推荐默认

* `r = 0.003`（0.3%），`S` 取 ATR 或结构/盘口止损位到入场价的点数。
* 建议 `N ≥ 1` 时下单，否则不下或延迟。

---

## 5. 动态缩放因子（示例）

* 结构/盘口一致性：`f_sig ∈ {0.25, 0.5, 1.0}`
* 波动与回撤：`f_vol, f_dd ∈ (0, 1]`
* 实际下单：`N_real = max(1, floor( N × f_sig × f_vol × f_dd ))`

---

## 6. 账户级断路器（基础）

* 当日亏损 ≥ **3×R0** 或连续亏损 ≥ 3 笔 → **停止当日交易**。
* 强平事件后遵循 G 规则（见第 9 章）。

---

## 7. 与策略/盘口模块对接

* **策略产出**：方向、入场价、止损 S、（可选）止盈、置信度/评分。
* **盘口产出**：`trend_score`、`fake_breakout_prob`、`wall_state`。
* **统一交付**给“仓位计算（S） + 规则引擎（G） + 执行控制”。

---

## 8. 指标与日志

* 记录每笔：Eq、R、S、N（建议/实际）、缩放因子、规则命中、下单/成交/退出原因。
* 便于复盘与参数自适应。

---

## 9. 统一规则体系（S & G）与页面设计（方案 A：一个面板 + 标签）

> 将方法论落地为 **S 规则（Sizing Policy，建议）**，并用 \*\*G 规则（Guardrails，硬限制）\*\*保障组合安全。
> 左侧“Position & Risk Controls”面板新增 **Tabs：`G规则` / `S规则`**；右侧“Notifications”面板保持不变。
> **下单弹窗**仅展示 **S 规则即时建议**（只读），不做配置修改。

### 9.1 S 规则（Sizing Policy：按方法论算“该下多少仓”）

流程：**S0→S1→S2→S3→S4→S5→S6→S7→S8**，得出 `N_sizing`（建议仓位），再交给 G 规则审查与裁剪。

* **S0｜资格与时段过滤（事件/时段）**
  可交易时段、黑名单事件窗口（财报、FOMC 等）。
  *UI*：交易所/品种时段、禁入窗口模板。
* **S1｜每笔风险预算 R（资金/回撤自适应）**
  `R0 = Eq × r_base`；`f_dd(MDD)`（例：0~~5%→1.0；5~~10%→0.7；>10%→0.5）→ `R = R0 × f_dd × f_vol_acct(可选)`。
* **S2｜止损距离 S（以波动定仓）**
  优先：`S_strategy` > `ATR×N` > `最小tick×k`； `S = max(...)`。
  *UI*：ATR 窗口、N 倍数、最小 S。
* **S3｜基础单位数**
  期货：`N0 = floor( R / (point_value × S) )`；
  个股（风险驱动）：`shares0 = floor( R / |Entry - SL| )`。
* **S4｜信号/一致性缩放**
  `f_sig`（0.25/0.5/1.0 或线性组合），`N1 = floor(N0 × f_sig)`。
* **S5｜目标波动率校准（可选）**
  `f_vol = target_vol / realized_vol_recent`（裁剪到 `[0.5, 1.5]`），`N2 = floor(N1 × f_vol)`。
* **S6｜相关性/集中度（组合层）**
  分组风险/敞口上限，计算 `f_corr` 约束 `N3`。
* **S7｜成交/深度约束（Level 2） & 个股预算驱动**
  以 Xbps 内深度与冲击上限，得 `N_exec_cap`；预算驱动个股：`budget = Eq/divisor_shares`。
  `N4 = min(N3, N_exec_cap)`；或 `shares4 = min(shares3, shares_budget)`。
* **S8｜整手与最小值**
  交易所步进/整手/最小合约取整；输出 `N_sizing` 与“因子拆解”用于复盘。

> S 规则的**参数设置与历史记录**在主页面 S 标签中；**下单弹窗**只展示即时计算结果，不改配置。

### 9.2 G 规则（Guardrails：账户/组合硬限制）

执行顺序严格：**G7→G6→G5→G4→G3→G2→G1**。

* **G7｜跨日停交易（强平后锁定）**
  触发 T2 强平后，**暂停之后两天**（第 3 个交易日恢复）。
* **G6｜当日停/冷却（行为）**
  当日两笔亏损→停止当日；单笔亏损→冷却 120 分钟（可配）。
* **G5｜日内交易次数上限**
  美东 0:00–24:00 **最多 3 次**（开+平计 1 次）。
* **G4｜杠杆感知的亏损阈值（通知/强平）**
  三种基准（可组合）：

  1. `Equity/L：T = Eq × pct_equity / max(1, L)`
  2. `保证金：T = total_initial_margin × pct_margin`
  3. `敞口：T = gross_exposure × pct_exposure`
     触发：`loss_abs ≥ T1` → 通知；`≥ T2` → **强平 + 限制新单**（并触发 G7）。
* **G3｜浮亏禁止加仓**
  任一方向浮亏时，禁止同向加仓。
* **G2｜排队/滑点与挂单限制**
  前单未完全成交→禁再下同向单；滑点超阈→阻断。
* **G1｜资产级硬上限（保证金×缓冲；单笔≤1/4）**
  期货：`max_lots = floor( Eq / (initial_margin × buffer) )`；单笔上限 `= floor(max_lots × 0.25)`；
  个股：在 S 结果基础上受组/资产上限裁剪（名义/仓占比等）。

## 12. 接口与数据流（要点）

* **S 配置**
  `GET/PUT /api/sizing/policy`（全局 + 资产级参数）
  `GET /api/sizing/history?symbol=&since=`（S 建议历史）
* **S 预览（下单弹窗）**
  `POST /api/sizing/preview` → `{ N, explain: { R, S, point_value, f_sig, f_vol, f_corr, depth_cap, ... } }`
* **G 校验**
  `POST /api/orders/validate`（执行顺序 `G7→G6→G5→G4→G3→G2→G1`；可附 `sizing_explain`）
* **下单**
  `POST /api/orders/place`（内部先 `validate`，通过才执行）
* **事件/日志**

## 13. 示例：MNQ 一次建议与校验（带入实参）

假设 `Eq = 100,000`、`r_base = 0.003`、`MDD ≤ 5% → f_dd = 1.0`、`S = 25 点`、`point_value = 2`：

* **S1**：`R = 100000 × 0.003 = $300`
* **S3**：单合约风险 `= S × PV = 25 × 2 = $50` → `N0 = floor(300/50) = 6`
* **S4**：若 `f_sig = 0.5` → `N1 = 3`（未触发 S5\~S7 时 `N_sizing ≈ 3`）
* **G1**：`max_lots = floor( 100000 / (3479.31 × 1.4) ) = floor(20.5) = 20`；单笔上限 `= floor(20 × 0.25) = 5` → 建议 3 手**不受限**
* **G2/G3/G4/G5/G6/G7**：按当前状态判定（如无触发则通过）。
