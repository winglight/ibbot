# WebSocket 数据修复开发任务

## 背景
切换数据库后，WebSocket 推送的仓位、策略、订单与日志数据出现全部为空或陈旧的问题。经排查链路为“页面 → 主程序 → 独立服务 → 缓存”，主要依赖 Redis 快照、独立服务健康状态以及 ib-command 结果流。针对现状需执行一揽子修复工作，并将仓位缓存刷新间隔调整为 15 秒。

## 任务拆解

### 1. Redis 与服务配置自检
- [ ] 在主程序启动流程中输出所有 Redis 连接的最终解析地址（`ACCOUNT_CACHE_REDIS_URL`、`DATA_LAYER_REDIS_URL`、`IBBOT_REDIS_URL` 等）。
- [ ] 新增运维脚本或启动检查，验证上述 Redis 指向同一实例并在不一致时报警。
- [ ] 编写部署文档，指导切换数据库时同步核对 Redis 配置。

### 2. 仓位快照刷新与兜底
- [ ] 将 `ACCOUNT_SNAPSHOT_REFRESH_INTERVAL_SECONDS` 默认值调整为 **15 秒**，并在配置文档中说明可通过环境变量覆盖。
- [ ] 更新 `AccountSnapshotService.refresh_positions`，当刷新失败时向前端推送明确的错误信息（包含 `stale_reason`）。
- [ ] 为仓位刷新逻辑补充单元测试，确保缓存超时与错误透传行为正确。

### 3. strategy-service 自愈能力
- [ ] 在 `StrategyRuntime.start` 结束后执行一次 Redis 元数据健康检查，若索引缺失则自动调用同步流程。
- [ ] 将健康检查结果写入服务健康上报，供主程序判断是否返回“服务不可用”。
- [ ] 增加策略元数据同步的日志，便于运维追踪。

### 4. orders-service 快照回源
- [ ] 启动时检测 Redis 中订单快照的时间戳，若早于当前部署时间或为空则清空并记录警告。
- [ ] 实现对 `stream:ib:results` 的一次性补拉逻辑，确保切换数据库后能够重建快照。
- [ ] 对长时间无新订单事件的场景写入日志并上报健康状态。

### 5. 日志面板路径配置化
- [ ] 将日志读取路径改为环境变量（例如 `LOG_FILE_PATH`）。
- [ ] 当日志文件缺失时返回明确错误并提示检查路径配置。
- [ ] 更新运维文档，说明日志路径配置方法。

### 6. 数据库切换一致性校验
- [ ] 为 orders-service 新增数据库连通性自检；失败时将健康状态标记为 `unhealthy` 并提示 Redis 数据可能陈旧。
- [ ] 编写数据库切换后的回归脚本，验证订单持久化与快照更新流程。
- [ ] 将自检结果接入监控或告警渠道。

## 交付物
- 更新后的服务代码（含单元测试）。
- 运维与部署文档更新。
- 一套用于切换数据库后快速验收的脚本或手册。

## 验收标准
- WebSocket 推送的仓位、策略、订单、日志数据均能在 1 个刷新周期内恢复真实内容。
- Redis 与数据库切换后，监控面板无健康告警。
- 仓位刷新间隔默认 15 秒，可通过配置调整。
