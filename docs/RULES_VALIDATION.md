# G Rules 和 S Rules 设置验证指南

## 概述
本文档说明如何验证 G Rules（全局规则）和 S Rules（仓位规则）设置的有效性。

## 验证方法

### 1. 前端验证
- **表单验证**: 在弹窗中填写配置时，前端会进行基本的表单验证
- **保存确认**: 保存成功后会显示绿色提示消息
- **配置回显**: 重新打开弹窗时会显示已保存的配置

### 2. 后端验证
- **API响应**: 保存时检查API返回的success状态
- **数据库存储**: 配置会持久化到strategy_settings表中
- **日志记录**: 查看服务器日志确认配置保存和加载过程

### 3. 功能验证

#### G Rules验证
1. 打开G Rules设置弹窗
2. 填写配置参数（如风险限制、交易时间等）
3. 点击"保存"按钮
4. 确认显示"G Rules配置已保存"提示
5. 重新打开弹窗验证配置是否正确显示
6. 检查实际交易中是否按照规则执行

#### S Rules验证
1. 打开S Rules设置弹窗
2. 配置仓位管理参数（如最大仓位、风险比例等）
3. 点击"保存"按钮
4. 确认显示"S Rules配置已保存"提示
5. 重新打开弹窗验证配置是否正确显示
6. 在实际交易中观察仓位分配是否符合设置

### 4. 技术验证

#### 数据库检查
```sql
-- 查看保存的配置
SELECT * FROM strategy_settings WHERE key IN ('g_rules_config', 'sizing_policy');
```

#### API测试
```bash
# 测试G Rules配置获取
curl -X GET "http://localhost:8000/g-rules/config"

# 测试S Rules配置获取
curl -X GET "http://localhost:8000/api/sizing/policy"
```

#### 日志监控
- 监控服务器日志中的配置保存和加载信息
- 检查是否有错误或警告信息
- 验证配置在系统重启后是否正确加载

## 常见问题排查

### 配置未生效
1. 检查前端是否显示保存成功提示
2. 验证API调用是否返回成功状态
3. 查看服务器日志是否有错误信息
4. 确认数据库中是否正确存储配置

### 配置丢失
1. 检查数据库连接是否正常
2. 验证strategy_settings表是否存在
3. 确认配置保存时使用的键名是否正确

### 规则不执行
1. 验证配置格式是否正确
2. 检查相关业务逻辑是否正确读取配置
3. 确认规则引擎是否正常运行

## 建议的测试流程

1. **单元测试**: 测试配置保存和读取的API端点
2. **集成测试**: 测试前端表单与后端API的完整流程
3. **功能测试**: 在模拟环境中验证规则的实际执行效果
4. **压力测试**: 测试大量配置更新时的系统稳定性
5. **回归测试**: 确保新功能不影响现有功能

## 监控建议

- 设置配置变更的日志记录
- 监控规则执行的成功率
- 定期备份重要配置
- 建立配置变更的审计跟踪
