# DOM 信号逻辑优化

目前 DOM 信号（多/空指示）触发得过于频繁，且缺乏明确意义。下面我们重构信号生成逻辑，以产生更少但更有价值的信号，并为其提供置信度，同时将这些信号直接叠加在K线图上以提高清晰度。

## 1. 降低信号频率并引入置信度分数（-1 到 1）

**问题：** 现有逻辑对单次快照指标使用固定阈值（例如 OBI5 > 0.6 判多、< 0.4 判空，并用 OFI 的符号确认）。在较高的 DOM 刷新频率下（前端下采样后仍约每秒 1–2 次），即便是围绕阈值的正常波动也会几乎每秒触发一次信号，导致“Long/Short”快速闪烁，缺乏可操作性。

**解决思路：** 采用更科学的阈值与聚合方法。算法不再关注单一瞬时值，而是考虑**最近一段时间窗口**内的 DOM 数据，并在每次评估时输出一个位于 **\[-1, 1]** 的置信度分数：

* **连续置信度分数：** 用连续的趋势置信度取代二元的 `m.long/m.short` 标志，其中 +1 表示完全看多，-1 表示完全看空；中间值代表混合或不确定的情形。可命名为 `trend_score`，与设计中预期输出一致。例如，0.8 表示强偏多，-0.3 表示轻度偏空。

* **滑动窗口分析：** 不再用单点，而是用最近 N 秒或最近 M 个快照来计算该分数。简单的滑动窗口能平滑噪声：

  * 计算过去 N 秒的 **平均 OBI** 与 **累计 OFI**（或每秒平均 OFI）。这能体现**持续性失衡**。例如，如果 30 秒内 OBI 持续较高（\~0.65）且净 OFI 显著为正，则置信度应接近 +1；反之则接近 -1；若两边拉锯或振荡，则接近 0。
  * 或采用**频率法**：统计过去 N 内多少比例的快照呈现多头/空头偏向。例如最近 100 个快照中，若 80% 符合多头条件（OBI > 0.6 且 OFI > 0），则置信度 = +0.6（表示 60% 强度的多头占优）。本质上衡量的是**某一方优势的持久度**。

* **按强度加权：** 更细致的方法是按信号强弱加权：

  * **OBI 加权：** 使用归一化 OBI = (OBI5 - 0.5) \* 2，将 0–1 映射到 -1…+1（卖方占优为负，买方占优为正）。在窗口内求其平均，得到偏置分量。
  * **OFI 加权：** 使用 OFI 在窗口内的**累加和**（或带符号的平均 OFI）。大的正累计 OFI 表示强劲的主动买压，增强多头置信度；大的负累计值则增强空头置信度。
  * **组合**（示例）：`confidence = w1 * avg_norm_OBI + w2 * sign(cum_OFI) * min(1, |cum_OFI|/threshold)`。权重 w1、w2 可调，使订单簿失衡与订单流共同发挥作用。最终将分数裁剪到 \[-1,1]。

* **Z 分值触发：** 利用 Z-OBI、Z-OFI 设置**动态阈值**。例如，要求 Z-OBI > z₀ 且 Z-OFI > z₀ 才视为强信号。与其用固定 OBI=0.6，不如用“OBI 处于其近期分布的前 5%（高 z-score）”，OFI 同理。这样仅在**统计显著**的盘口事件上触发信号。该逻辑也可纳入置信度：

  * 若 Z-OBI > 2 且 Z-OFI > 2，则强力将置信度推向 +1（或负向时推向 -1）。
  * 若 Z 值徘徊在 0 附近，则即便 OBI 偶尔 >0.6，置信度也保持较低（避免正常波动误触发）。

* **持续性约束：** 为进一步抑制噪声，要求条件**保持最短时长**或**重复出现**才触发。例如，只有当置信度连续数秒都高于 +0.7（或连续若干快照均为多头）才发出 Long 信号。这能过滤“单跳假动作”。DOM 高频（原始 10Hz）下，等待 2–3 秒（约 20 多个快照）即可显著减少“闪烁”。

**效果：** 结合以上方法，多空信号频率会降至**有意义**的水平。结合用户经验（活跃时段约 0.5–1.5 小时/天、最多 3 次交易动作），调参后应在该时段内只产生**少量高置信度信号**，而非每分钟几十个。系统每一时刻输出一个平滑的置信度指示；只有当其跨越高阈值（如 Long 入场 > 0.8、Short 入场 < -0.8）时才触发展示/执行信号，并最好配合**迟滞**（例如一旦触发 Long，需要置信度回落到较低阈值（如 < 0）后才允许再次触发 Long）以避免短时间内重复触发。

**置信度的展示与使用：** 不再频繁闪“Long/Short”文字，UI 可显示一个**趋势条或数值**实时更新（如“Trend Score: +0.75”并以绿色展示）。这让交易者直观看到 DOM 对哪一侧更有利。只有当分数极高或极低时，才将其视为具体交易信号（下一节将把它标注到K线图上）。这种“百分比式置信度”更符合人工判断（“偏多，置信度中等”），而非生硬的二元开关。

**与设计目标一致性验证：** 该方案呼应了文档中预期的 `trend_score` 概念。文档建议输出 `trend_score ∈ [-1,1]` 并用于仓位调整与风控，这证明**连续型置信度**是更理想的表达。当前我们用 OBI/OFI 的历史窗口实现了一个**启发式版本**（暂替代训练模型）。后续可演进为学习型模型（文档亦提出训练用于趋势/假突破评分的 ML 模型），但在此过渡方案下，信号的**可操作性与可信度**已显著提升。

## 2. 将信号与K线图（Candlestick/K-line）融合

**问题：** 现有 DOM 信号可视化（顶部左右滑动的红/绿短柱）与价格图表**脱节**，很难看出每个信号对应的具体时间。该“信号条”本质上是一个独立时间轴（每来一个事件就整体右移），与K线的真实时间轴**错位**，交易者无法判断某个 Long 信号是在某次价格波动之前还是之后。

**解决方案：** **移除**独立滚动信号条，将交易信号**直接叠加**在K线图的**正确时间戳**上：

* 在K线上标注“最佳买/卖点”的图标或注记。例如：

  * **买入信号**：在对应K线**下方**放置绿色上箭头（↑）。
  * **卖出信号**：在对应K线**上方**放置红色下箭头（↓）。
* 箭头应**正好出现在信号生成的时间点**（纵向位置可取该K线的**低点/高点**或**中位价**，可由UI决定）。

**置信度等级展示：** 由于需要 3 或 4 档置信度，可按当时的置信度对标记样式进行区分：

* 用**颜色深浅**或**尺寸大小**表达强弱。例如：Level 1（低置信度）用小且空心的箭头，Level 4（非常高）用更大且实心的箭头；中间档位用中等大小/半透明等。
* 或使用不同形状/标识（如添加星标）。但保持箭头主题并用大小/不透明度区分通常最直观。

**四档示例（置信度范围）：**

* 0.5 ≤ 分数 < 0.7：**Level 1**（轻度）— 小、浅色箭头
* 0.7 ≤ 分数 < 0.85：**Level 2** — 中等箭头
* 0.85 ≤ 分数 < 0.95：**Level 3** — 大箭头
* ≥ 0.95：**Level 4**（极强）— 大箭头并额外高亮（描边或双箭头）

（若采用三档，可合并为低/中/高并调整阈值。）

**时间对齐：** K线图以**真实时间**为横轴，箭头叠加其上天然就**时间对齐**。若信号在 10:30:25 触发，它会落在约 10:30 的那根K线上。这解决了此前的歧义——用户能轻松查看信号前后价格行为。反观旧的移动短柱没有明确时间刻度，只有相对位置。

**移除快速“跑马灯”短柱：** 将快速滚动的信号条完全移除。那些短柱本质上是在滚动展示各类事件（如 buy\_absorb、sweep\_up/down 等）的小矩形。它们虽能体现频率，但**不可操作且易引起混乱**。真正重要的事件将通过**置信度/分数**体现，并在K线上显示。详细的事件（吸收、扫单等）仍可记录在**告警表**中供深入查看，但不必全部实时可视化，从而**显著简化 UI**。

**与价格联动：** 将信号叠加在K线后，能直观看到其与价格的关系。例如，若 DOM 失衡先于价格上行，一个绿色“Long”箭头就会出现在上冲之前，给出直观反馈；若出现信号但价格未跟随（假信号），也能一目了然。随着时间推移，用户能通过回看带箭头的图表**评估信号可靠性**。

**提示/细节：** 可为信号标记加上悬浮提示或点击详情，例如：“Long Level 3 – TrendScore 0.88（强买倾向）”，让用户了解触发原因（置信度、关键组件指标或触发事件）。

**总结：** 该重构使 DOM 信号与行情图表**紧密耦合**，令其成为**可操作的指标**而非抽象旗标。它解决了对齐问题（信号与x轴时间精确匹配），并通过置信度展示强化“重要性”的可读性。交易者只需关注一张图（价格图）即可同时看到价格与信号，显著提升可用性。
